## What was fixed

Three small fixes, nothing else touched.

**1. `internal/service/user_service.go:26` — compile error**
The two-value call was being used in a single-value context and paired with `, nil`.
Now the repository result is returned directly:

```go
return s.userRepo.CreateUser(
	ctx,
	username,
	email,
	passwordHash,
)
```

**2. `internal/handler/user_handler.go:22-24` — syntax error**
Removed the trailing commas after the struct tags in `CreateUserRequest`.
Struct fields are newline-separated, not comma-separated.

**3. `app/.env` — env var typo**
`db_SSLMODE` → `DB_SSLMODE`. Lookup is case-sensitive, so `cfg.Database.SSLMode` had been
resolving to empty and the DSN ended with `?sslmode=`.

## Current architecture

```
cmd/server/main.go        config.Load -> database.NewPostgresPool -> repository -> service -> handler -> router.New -> r.Run(:PORT)
internal/config           env-backed Config (godotenv, .env)
internal/database         pgxpool with a 5s connect/ping timeout
internal/repository       User{ID, Username, Email, PasswordHash}; CreateUser via INSERT ... RETURNING
internal/service          UserService — currently a pass-through to the repository
internal/handler          UserHandler.CreateUser — gin binding + JSON responses
internal/router           GET /, GET /health, POST /users
```

Infra: `docker-compose.yml` runs `postgres:13` as `guildchat-postgres` on 5432, db `guildchat`.
The `users` table already exists with `id, username, email, password_hash, created_at, updated_at`
and unique constraints on `username` and `email`.

## Known gaps (deliberately not addressed)

These are real, but out of scope for the compile fixes — listed so they aren't forgotten.

1. **Passwords are stored in plaintext.** `req.Password` goes straight through the service
   into the `password_hash` column. Confirmed above: the `201` response echoed
   `"PasswordHash":"secret"`. Needs bcrypt/argon2 in the service layer.
2. **The response leaks the password hash** and uses Go field names, because
   `repository.User` has no `json` tags. Needs a response DTO or tags with
   `json:"-"` on the hash.
3. **Duplicate username/email returns `500`.** It's a `23505` unique violation and
   should map to `409 Conflict`.
4. **Error detail is discarded** — the handler logs nothing and returns a generic string,
   so the real DB error is invisible.
5. **`created_at` / `updated_at` are never read.** They exist in the table but not on the
   `User` struct, so the API can't return them.
6. **`app/Dockerfile` and `app/.env.example` are empty (0 bytes).** Compose only covers
   Postgres; the API is run by hand.
7. **Gin runs in debug mode** and trusts all proxies — fine locally, not for deployment.
